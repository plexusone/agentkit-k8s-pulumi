# AgentKit Kubernetes Pulumi v0.1.0 Release Notes

**Release Date:** July 13, 2026

## Highlights

Initial release of the Kubernetes deployment provider for AgentKit. This module enables cloud-agnostic container deployments across EKS, GKE, AKS, and on-premises Kubernetes clusters using Pulumi.

## Features

### Kubernetes Provider

A complete `deploy.Provider` implementation for Kubernetes workloads:

```go
import (
    "github.com/plexusone/agentkit/deploy"
    _ "github.com/plexusone/agentkit-k8s-pulumi/deploy/providers/kubernetes"
)

// Auto-registered via blank import
provider, err := deploy.GetProviderByName(deploy.ProviderKubernetes, cfg)
```

### Cloud-Agnostic Deployments

Deploy the same agent to any Kubernetes cluster:

| Cloud | Service | Status |
|-------|---------|--------|
| AWS | EKS | Supported |
| GCP | GKE | Supported |
| Azure | AKS | Supported |
| On-prem | Any K8s | Supported |

### Kubernetes Resources

The provider creates standard Kubernetes resources:

- **Deployment**: Container spec, replicas, resource limits, probes
- **Service**: ClusterIP, NodePort, or LoadBalancer
- **Ingress**: Optional, with TLS support

### Configuration Options

Kubernetes-specific configuration via provider extensions:

```go
cfg.ProviderOptions = map[string]any{
    "namespace":          "agents",
    "serviceType":        "LoadBalancer",
    "replicas":           3,
    "ingressEnabled":     true,
    "ingressHost":        "agent.example.com",
    "ingressClassName":   "nginx",
    "ingressTLSEnabled":  true,
    "ingressTLSSecret":   "agent-tls",
    "serviceAccountName": "agent-sa",
    "nodeSelector":       map[string]string{"node-type": "agent"},
}
```

### Pulumi Automation API

Built on Pulumi's automation API for programmatic infrastructure management:

- No CLI required - pure Go
- State management via local file or S3 backend
- Preview and destroy operations

## Installation

```bash
go get github.com/plexusone/agentkit-k8s-pulumi@v0.1.0
```

## Requirements

- Go 1.26+
- agentkit v0.7.0+
- Kubernetes cluster with kubectl access
